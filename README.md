# BR | Server Manager — Telegram-бот

Панель управления для игрового сервера: роли, отчёты, заявки, наказания, баллы,
логирование — всё завязано на Google Sheets.

## 1. Установка

```bash
pip install -r requirements.txt --break-system-packages
```

## 2. Настройка

Заполните переменные окружения (или отредактируйте `config.py` напрямую):

```bash
export BOT_TOKEN=728282727:GvJhgGHhj....."
export CREATOR_ID="6140351301"
export GOOGLE_CREDENTIALS_PATH="/путь/к/credentials.json"
export GOOGLE_SHEET_ID="ID_вашей_гугл_таблицы"
export GEMINI_API_KEY="AIza..."         # бесплатный тариф — обязателен для распознавания отчётов
```

`credentials.json` — это JSON-ключ сервис-аккаунта Google (Google Cloud Console →
IAM → Service Accounts → Keys). Не забудьте выдать этому сервис-аккаунту доступ
редактора к самой таблице (Поделиться → email сервис-аккаунта).

При первом запуске бот сам создаст недостающие листы: `Пользователи`, `Заявки`,
`Логи_доступа`, `Логи_наказаний`, `Логи_баллов`, `Логи_доп_работ`, `Логи_модераторов`.
Лист `Список` (основная таблица со статистикой, как на ваших скринах) должен уже
существовать — бот только читает/пишет в его столбцы (`Должность`/A, `NickName`/B,
`Дата назначения`/C, `Баллы`/K, `Строгие выговоры`/L, `Предупреждения`/M,
`Устные выговоры`/N, `Общее количество дней`/O).

## 3. Запуск

```bash
python main.py
```

## 4. Что уже реализовано

- `/id`, `/start` (верификация: VK → Discord → форум → возраст → часовой пояс →
  Telegram @username → почта), `/join`, `/leave`, `/info`, `/members`
- Главное меню: 📊 Статистика, Заявления, 🔴 Панель управления (по ролям)
- Заявления: Отчёт (альбом скриншотов + автоматический подсчёт баллов через Gemini
  Vision), Неактив, Доп.баллы (доп.работа), Снятие наказаний
- Панель управления: добавить/удалить/список пользователей, +/- баллы,
  +/- наказание, рассмотрение заявок (одобрить/отказать с причиной)
- Выдать доступ (Старший состав / Лидер / Следящий / Старший следящий) с учётом
  иерархии и групп организаций (Соц / Силовые / ОПГ)
- Логирование: логи доступа, наказаний, баллов, доп.работ; логи модераторов
  (руководство+)
- Руководство: `/settings`, `/reset`
- Создатель: `/o`, `/allreset`, `/setinfo`, «Назначить руководство»
- `/ip` — прокси-команда к вашему существующему `ip.py` (положите файл рядом
  с `main.py` и определите там `handle_ip(message)`)

## 5. Что нужно доделать/проверить перед продакшеном

1. **Формат листа "Список"**: скрипт ищет пустые слоты по столбцам A (Должность)
   и B (NickName) внутри блока организации — проверьте, что в вашей таблице
   заголовки организаций (`Арзамасская ОПГ`, `Батыревская ОПГ`, …) действительно
   находятся в столбце A так же, как на скриншотах.
2. **AI-распознавание отчётов** (`services/ai_ocr.py`) — использует Gemini Vision
   и парсит поля `Онлайн`/`Ответов`. Норматив по умолчанию 110/140 — можно задать
   свой на пользователя через колонки `NormOnline`/`NormReport` листа
   `Пользователи`.
3. **Доступ к Google Sheets по ролям** (лидеру — reader, следящему и выше —
   writer) в спеке упомянут отдельно от кода бота: это делается через Google
   Drive Sharing API. Для этого в `services/sheets.py` можно добавить вызов
   `drive_service.permissions().create(...)`, использующий email пользователя
   (нужен Google-аккаунт человека, а не Telegram) — этого email в текущей схеме
   нет, уточните у пользователя, откуда его брать.
4. **Отчётность (архив за 4 недели → в тг-канал)** и разделы "Заявки" для
   лидеров/следящих с фильтром "кто чей отчёт может смотреть" — реализованы
   частично (`review.py` покрывает одобрение/отказ доп.работ/неактивов/снятий
   наказаний); отдельный архивный экспорт отчётов в канал нужно дописать под
   ваш канал (id канала, расписание через `APScheduler` или cron).
5. **Токен бота засвечен** в переданном файле и в этом чате. Раз это тестовый
   бот — ок, но перед продакшеном перевыпустите токен через @BotFather.

## 7. Отчётность через Google Gemini Vision (бесплатный тариф)

### Как получить GEMINI_API_KEY (бесплатно, без карты)

1. Зайдите на **aistudio.google.com**, войдите через Google-аккаунт.
2. Нажмите **Get API key → Create API key**.
3. Скопируйте ключ (вида `AIzaSy...`) и пропишите его в `GEMINI_API_KEY`.

Бесплатный тариф даёт ограниченное число запросов в минуту/день (актуальные
цифры — на ai.google.dev/pricing, на момент написания ~15 запросов/мин).
В `config.py` это отражено переменными `GEMINI_RPM` и `GEMINI_MAX_CONCURRENCY` —
если ваш аккаунт даёт другие лимиты, поправьте их.

### Очередь запросов при массовой сдаче отчётов

При 130 сотрудниках, сдающих отчёты одновременно, часть запросов неизбежно
упрётся в лимит запросов/минуту. Чтобы бот не падал с ошибкой 429, все вызовы
к Gemini идут через:

- `utils/rate_limiter.py` — скользящее окно на `GEMINI_RPM` запросов/60 сек:
  лишние запросы просто ждут своей очереди (не отклоняются, не теряются);
- семафор на `GEMINI_MAX_CONCURRENCY` одновременных запросов;
- автоматический ретрай с экспоненциальной паузой (2с → 4с → 8с → 16с) если
  всё-таки прилетела ошибка квоты/лимита.

Практически это значит: если все 130 человек одновременно нажмут «Отправить
отчёт», обработка растянется на несколько минут (130 / 15 ≈ 9 минут при
последовательной обработке), но никто не получит ошибку — каждый дождётся
своей очереди и результата.

### Логика разбора альбома

Кнопка «Отчет» принимает **альбом скриншотов** (несколько фото одним
сообщением в Telegram), а не один скрин. Разбор идёт в `services/ai_ocr.py`:
модель сама смотрит на весь альбом и определяет для каждого фото категорию —
`vch` (поход на ВЧ), `online` (окно точного времени), `interview`
(собеседование), `lecture` (лекция), `training` (тренировка), `rp`
(РП-ситуация) — а также проверяет дату/время в правом нижнем углу фото и
отбрасывает несовпадающие по дате скрины, схлопывает дубликаты активностей,
случившиеся ближе чем `MIN_MINUTES_BETWEEN_SAME_ACTIVITY` минут друг от друга
(в `config.py`, по умолчанию 30 мин). Работает в любое время суток — это
обычный API-запрос, без привязки к рабочим часам.

### Ранги и нормативы по организациям

- У каждого сотрудника теперь есть поле `Rank` (ранг: 7/8/9 — задаётся при
  добавлении пользователя в панели управления).
- Создатель настраивает норму через «Панель управления → Настроить
  нормативы»: выбирает организацию → ранг → вводит требуемое количество ВЧ /
  собеседований / лекций / тренировок / РП и требуемые часы онлайна. Данные
  хранятся в листе `Нормативы`.
- При сдаче отчёта бот сравнивает результат разбора альбома с нормативом
  именно для (организация сотрудника, его ранг) и начисляет баллы только если
  норма выполнена целиком (см. `score_report()` в `ai_ocr.py` — при желании
  поменяйте логику: например начислять частично за каждую выполненную
  категорию).
- Списки `ACTIVITY_TYPES`, `RANKS`, очки за категорию (`POINTS_PER_ACTIVITY_*`)
  — всё в `config.py`, легко расширяется под новые типы активностей/рангов.

### Что стоит проверить/доработать

1. Промпт в `ai_ocr.py` описывает правила текстом — точность распознавания
   зависит от качества скринов и того, насколько по делу описаны признаки
   (цвета сообщений, формулировки). Если модель путает категории — правьте
   `_SYSTEM_PROMPT`, это самый быстрый способ подкрутить точность без
   изменения кода.
2. Сейчас бот молча выставляет 0 баллов, если норма не выполнена целиком по
   ХОТЯ БЫ ОДНОЙ категории (см. `fully_met` в `score_report`). Если нужно
   частичное начисление — уберите блок `if not fully_met: points = 0`.
3. Альбом собирается через `media_group_id` с дебаунсом 1.5 сек
   (`_ALBUM_DEBOUNCE_SEC` в `applications.py`) — если у пользователей плохой
   интернет и фото альбома приходят с задержкой, увеличьте это значение.
4. Обязательно протестируйте на реальных скриншотах из игры перед раскаткой
   на всех — точность классификации текстовых сообщений в чате (особенно
   отличение lecture/training/rp друг от друга) стоит перепроверить вручную
   на 15–20 примерах.

## 8. Исправление краша `WorksheetNotFound: Список`

Эта ошибка означает, что в вашей Google-таблице нет вкладки с названием ровно
`Список` (с большой буквы, без пробелов). Либо переименуйте вкладку со
статистикой сотрудников в `Список`, либо поменяйте `SHEET_MAIN` в
`config.py` на точное название вашей вкладки. Теперь при старте бот сразу
покажет понятную ошибку со списком существующих вкладок, вместо трассировки
aiogram. Также добавлен глобальный обработчик ошибок (`@dp.errors()` в
`main.py`) — при любом непредвиденном исключении бот больше не роняет весь
процесс, а присылает пользователю «⚠️ Произошла ошибка...» и пишет полный
traceback в консоль.

## 9. Структура проекта

```
br_bot/
  config.py                 # токены, роли, организации, ранги/активности
  states.py                 # все FSM-состояния
  main.py                   # точка входа + глобальный обработчик ошибок
  services/
    sheets.py                # обёртка над Google Sheets (gspread) + нормативы
    ai_ocr.py                # распознавание альбома скриншотов отчётов (Gemini Vision)
  middlewares/
    access.py                # блокировка пользователей без доступа
  keyboards/
    menus.py                 # все инлайн-клавиатуры
  utils/
    access.py                 # кэш ролей/доступа
  handlers/
    common.py                 # /id /start /join /leave /info
    verification.py           # верификация нового сотрудника
    stats.py                   # "Моя статистика"
    applications.py            # Заявления (отчёт-альбом/неактив/доп.работа/снятие)
    admin_panel.py              # панель управления: добавить(+ранг)/удалить/список
    points_punish.py             # +/- баллы, +/- наказание
    review.py                     # рассмотрение заявок руководством
    grant_role.py                  # выдать роль / назначить руководство
    logging_panel.py                # логи доступа/наказаний/баллов/доп.работ
    leadership_creator.py            # /members /settings /reset /o /allreset /setinfo
    ip_command.py                     # /ip — обёртка над вашим ip.py
    norms.py                           # настройка нормативов по орг+рангу (создатель)
```
